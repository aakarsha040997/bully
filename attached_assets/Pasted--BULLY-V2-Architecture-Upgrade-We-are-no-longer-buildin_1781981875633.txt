# BULLY V2 - Architecture Upgrade

We are no longer building a simple productivity tracker.

We are building an Android-first AI accountability app that piggybacks on Android's UsageStatsManager.

**Do NOT redesign the UI.**
The current UI is good enough.
Focus on architecture, maintainability, and intelligence.

---

# Current Architecture

Already exists:

* services/usageStats.ts
* services/notifications.ts
* services/monitoring.ts (new)
* services/roastEngine.ts (temporary)
* Android UsageStats native module
* Expo Notifications
* Dashboard
* Settings
* Usage permission flow

Goal:

Android UsageStats
→ Monitoring Engine
→ Behavior/Roast Engine
→ Notification Service
→ Dashboard

The dashboard should NEVER decide when notifications are sent.

---

# IMPORTANT PRINCIPLES

1. Android UsageStatsManager is the SINGLE source of truth.

Do NOT build our own tracking engine.

Read Android usage.

Never duplicate Android tracking.

---

2. Monitoring makes decisions.

Notifications only display messages.

Dashboard only displays information.

Keep these responsibilities completely separate.

---

3. Everything must be modular.

No huge files.

No duplicated roast text.

No business logic inside React components.

# Cooldown Engine

Never repeat the same roast.

Remember recent roast IDs.

Respect cooldowns.

Avoid showing similar notifications repeatedly.

---

# Selector

Weighted random selection.

Frequently used roasts become less likely.

Recently shown roasts should almost never appear again.

---

# Monitoring Service

Rewrite services/monitoring.ts.

It should:

Read UsageStats.

Determine current behavior.

Run the rule engine.

Generate a roast.

Return a decision object.

It MUST NOT display notifications.

It MUST NOT know React exists.

It MUST NOT know about screens.

---

# Notifications

scheduleNotification()

Do not generate roast text here.

Do not decide when to notify.
