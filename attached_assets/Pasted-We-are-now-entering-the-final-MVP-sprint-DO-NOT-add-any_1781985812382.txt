We are now entering the final MVP sprint.

The next sprint is entirely about making Bully reliable and production-ready.

---

# Goal

Make Bully behave like a real Android service instead of a screen-based app.

---

# Priority 1 (Highest)

Implement reliable Android background monitoring.

Requirements:

* Use Android WorkManager (or the best native Android approach compatible with Expo development builds).
* Execute approximately every 15 minutes.
* Read Android UsageStatsManager.
* Run the existing monitoring engine.
* Respect cooldowns.
* Respect notification settings.
* Never spam notifications.
* Keep battery usage minimal.
* Do NOT duplicate Android tracking.
* Android UsageStatsManager remains the single source of truth.

If WorkManager cannot reliably detect foreground usage because of Android platform limitations, clearly document those limitations and implement the most reliable alternative available.

---

# Priority 2

Improve UsageStats onboarding.

Build a proper onboarding flow.

Instead of only opening Android Settings, explain:

Why Usage Access is needed.

How to enable it.

What data Bully reads.

What data Bully does NOT read.

Add:

Permission status

Success state

Denied state

Retry flow

Animated instructions if possible.

---

# Priority 3

Improve notification quality.

Requirements:

* Different notification titles.
* Better notification grouping.
* Android notification channel configuration.
* Prevent duplicate notifications.
* Better deep linking when notification is tapped.
* Track delivered notifications for cooldowns.
